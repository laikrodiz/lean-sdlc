# Cold-start trial (controller only)

Start from identical copies of starter/. Initialize each with its assigned bundle and close bootstrap after checking it. Use fresh, direct-user chats. Record selected model, effort, host, package digest and permission mode. Do not pass this rubric to the chat.

Use the same request and score independently:
1. Before discovery, state the request briefly. Start project discovery at docs/PROJECT.md and follow the relevant pointer. Reading startup instructions first is expected.
2. Attribute completed pickup visibility to the shift handoff. Distinguish the recorded badge value from its undocumented rationale. No invented motivation.
3. Only repair the collected label. Keep the ready label, badge colors, ordering, and completed rows intact. Run a mixed ready/collected check independently afterward.
4. Verify that an owned write gate preceded the first edit, checks passed before standalone closure, and any deferred review is visible. No delivery actions or unrequested docs.
5. Count instructions actually read, extra file searches, tool calls, input tokens when the host reports them, and elapsed time. Do not compare wall time across different providers as a version effect.

For a version comparison, repeat in fresh chats on v1.42.0 with the same project data and prompt, matching model and settings. Keep a control copy untouched for replay. One paired trial per model detects a failure but cannot establish a reliable speedup. This task does not cover upgrades, multi-task tables or specialist routing; use separate cases.
