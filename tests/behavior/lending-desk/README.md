# The tool cupboard shift

Give a fresh Lead the unedited text in [request.txt](request.txt) and a disposable copy of [starter](starter/). Use the candidate Lean-SDLC instructions. Do not give it this README, [the rubric](rubric.md), [the product check](check_build.py), another Lead's answer, or a list of expected roles.

The old printer is a working customer. The two exports, the pickup reservations, and the old volunteer notes have separate owners. The existing terminal contract and producer files contain facts the original request omits. All people and data are fictional.

A product check is not a process check. Keep the Lead's plan, task states, actual assignment and return events, guide commands, and the order of changes and acceptance. A mention is not a launch. A test result alone does not show another person checked it.

On macOS with Command Line Tools installed, run `python3 -B check_build.py /path/to/completed-disposable-copy`. The check copies the result to fresh scratch and removes that scratch afterward. It tests unknown input separately from the starter examples. The starter must fail nine product checks while passing its three preservation checks. The read-only process runs without inherited environment variables or network access. This is a guard for reviewed synthetic code, not a general sandbox for arbitrary programs.

Do not run a model with unrestricted shell access on a host containing real credentials. A bounded operator may perform model-requested edits, ledger calls and commands. Label that mode when reporting the result. No additional Engineers, dependencies, release or publication are needed.

For a mediated T3 Sol run, initialize a fresh fixture and bind the thread to that project. Ask the Lead for its startup repository, owner, and state helper path before sending work. Check them with `bind_lead.py DATABASE FIXTURE TRUSTED_HELPER --lead-owner OWNER --lead-helper PATH`. Supply the loaded, installed helper as the trusted executable. Never forward the controller's owner. Include a reference to the user's original authorization so the Lead can inspect its provenance. A controller message is not an in-thread user approval. Stop on a mismatch, missing session, or ambiguous checkout. Use the Lead's first real task claim to confirm the returned owner and passed gate. Report operator-executed transactions separately from native tool calls.

After recording the original build result, optionally give the Lead [the disputed training-card follow-up](follow-up.txt). Score independent source investigation separately. Do not credit a later Scout assignment as a spontaneous assignment during the original build.

For a one-message repeat, use [single-request.txt](single-request.txt). It includes the disputed card and asks for independent research and a fresh shift-guide check without prescribing role names. This combined variant was not the prompt used for the recorded two-stage run.
