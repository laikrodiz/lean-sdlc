# One user message, no operator

This is a controller procedure, not a prompt for the participant. Use the T3 project and thread tools. Do not expose this directory, traces, grader, or previous builds to the participant. Do not run the subject with a shell on the personal host.

1. On the controller, run `python3 -B autonomous.py prepare worker.zip`. Transfer only the resulting archive to a disposable worker. Extract it. Install the bundled `marketplace` into the worker's dedicated Codex profile. Confirm its plugin files match the packaged candidate, including the local instruction edits. Do not upgrade the personal profile. Keep the controller and its secrets outside the worker.
2. On a **separate probe project** with the same profile, verify that a worker can edit a synthetic file, run the installed task helper, and launch a native same-checkout child. Use synthetic sentinels to verify it cannot read a sibling, grader, or host-private file. Check secret isolation out of band; never ask a participant to print its environment. Check child restrictions too. No shared home mounts, global account connectors or credential-bearing shell environment. If any control is missing, stop as a setup failure. A different project directory alone is not isolation.
3. Register **Friday cupboard** on that worker as the project. Open an empty top-level T3 thread pinned to **Sol 6.2 High**. The user sends `START.txt` once, directly there. Do not paste an operator contract. The worker gets no role list or rubric. The controller waits for completion, never sends a work order, and never performs a subject action. A mandatory host approval is a setup issue. A redundant model question with valid tools and sufficient authority is an observed workflow failure, not an invitation to coach.
4. After the run, obtain the actual run/model metadata, ordered tool actions and child launches, returns, and checkpoint receipts. Grade each item in `autonomous.OBSERVATIONS` against that trace. Use the observation status `pass`, `fail`, or `unverified` and an actual host event ID. A missing role needs a complete trace to score as a failure. Worker statements are not receipts. For verified absence, cite the terminal event of the complete run. Do not mark a role passed without the child's result. A model answer containing a plausible command is not an execution. Retain event IDs, not unfiltered tool output.
5. Put controller observations in a JSON object with `run_id`, `candidate`, `variant`, `revision`, and `checks` keyed by observation. Verify the loaded candidate before entering its digest. On the macOS controller use the existing offline checker **only after reviewing the synthetic code it will execute**. Run `python3 -B autonomous.py grade BUILD --run-id ID --candidate DIGEST --revision 1 --variant baseline --trace TRACE.json --report RESULT.json`. The receipt is exclusive: existing results cannot be overwritten. Run `python3 -B autonomous.py advance RESULT.json` (supply all receipts in order on later rounds).
6. Follow that decision without involving the participant. On a baseline pass, use `prepare --variant confirmation` with the unchanged plugin and a fresh project and context. On a diagnosed instruction miss, change only the responsible instruction **in a local candidate**, rerun the existing release checks, and start a fresh baseline. Never change a grader or fixture to rescue the current candidate. Cap at three candidate revisions. Stop on unsafe setup, missing evidence, unexplained failure, or a required user decision. Repeated runs require a host route authorized to start fresh workers: if that route requires a new human message every time, unattended repetition is **not** established.
7. Retain compact reports, build and receipts on the controller. After all processes stop and evidence is retained, archive only this trial's threads and remove its disposable fixture and project registration. Do not publish, install globally, or change hooks on the personal host.

The packager, product checker, ledger checks and round decisions are executable. T3 dispatch, trace interpretation and a justified instruction edit are controller-agent responsibilities. No scheduled or background service is installed by these scripts.
