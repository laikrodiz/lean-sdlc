# Execution Routing Workflow

Use after tasks are approved and before code starts when execution ownership is not already obvious.

Use Terra at `medium` or Sol at `low` for straightforward routing. Read [model-routing.md](model-routing.md) before delegating.

## Modes

1. Local: one ready task blocks the next critical step or ownership overlaps.
2. Delegated: at least two substantial tasks have disjoint write scope and exact proof paths.
3. Batch: a larger disjoint queue benefits from explicit integration checkpoints.

Unknown diagnosis goes to debugging before a worker receives implementation. Keep quick work local. Delegation must save meaningful wall time or main-agent context after assignment and review costs.

Every worker assignment states task id, acceptance, owned files, proof command, forbidden unrelated work, concurrent-change safety, and a concise return contract.

After execution, review scope and evidence, then route to verification. Use traceability for uncertain truth and documentation maintenance only for approved cleanup.

Success means ownership and model effort match the task without spending more on delegation than the work itself.
