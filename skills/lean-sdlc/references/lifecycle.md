# Lean-SDLC Lifecycle

Track three separate axes:

- `stage`: project maturity context
- `version`: current business promise
- `iteration`: current work loop

## Stage

Allowed stages are `discovery`, `foundation`, `delivery`, `operation`, and `evolution`. Use stage to frame decisions rather than describe every task.

## Version

Each meaningful version states why it exists now, who it serves, what outcome it promises, what is deferred, and what evidence closes it. Replace stale labels such as perpetual `MVP` when exit criteria are met.

## Iteration

Use the smallest required part of this loop:

`brainstorm -> refine -> decide -> plan -> implement -> verify -> reconcile`

Move backward when evidence invalidates earlier truth. Select one primary lane per turn instead of running the full loop mechanically.

## Exit Conditions

Route to versioning when version exit criteria are met, business context changes materially, the current promise is the wrong delivery cut, project maturity changes, or the current stage imposes the wrong constraints.
