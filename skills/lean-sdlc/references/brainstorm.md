# Brainstorm Workflow

Use when the project is still an idea and stable truth does not exist.

Use Sol at `high` for framing. Smaller models may summarize supplied material or format an agreed draft; keep problem, user, value, and scope judgments with Sol.

## Workflow

1. Ask what real problem hurts enough to solve now.
2. Identify who feels it directly.
3. Find the smallest useful outcome.
4. Record hard constraints.
5. Separate what can be postponed.
6. Identify only unavoidable early durable choices.
7. Challenge large assumptions with smaller alternatives.
8. Slice initial features by independently valuable behavior rather than modules or roadmap buckets.
9. Put prototype limits and volatile mappings in scope or lower technical docs.
10. Before drafting repository files, activate the bootstrap task or one planning-control task. Draft the project brief, scope, indexes, and initial feature or decision files only where justified.

Stop before detailed architecture or delivery implementation tasks. Do not choose a stack before real features are visible. Do not create decisions for preferences or features for entire capability areas.

Success means the project has a sharp why, explicit boundaries, current stage and version goal, and a small first set of behavior truth.
