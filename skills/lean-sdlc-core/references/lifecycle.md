# Lean-SDLC Lifecycle

## Three Axes

Track three separate axes at all times:

- `stage`: project maturity context
- `version`: current business promise
- `iteration`: current work loop

Do not collapse them into one vague label.

## Stage

Allowed stages:

- `discovery`
- `foundation`
- `delivery`
- `operation`
- `evolution`

Use stage to frame decisions, not to describe every task.

## Version

Each meaningful version must answer:

- why this release exists now
- who it serves now
- what outcome it promises
- what is deferred
- what evidence closes it

Do not leave a project trapped under a stale `MVP` label after its exit criteria have been met.

## Iteration

Use this loop:

1. brainstorm
2. refine
3. decide
4. plan
5. implement
6. verify
7. reconcile

The loop can move backward when new evidence appears. This is not waterfall.

## Exit Conditions

Propose a version transition when:

- version exit criteria are met
- business context changed materially
- the current version promise is no longer the right cut

Propose a stage transition when:

- the project maturity context changed
- the current stage rules are holding the project in the wrong mode
